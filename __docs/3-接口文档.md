# 一、HTTP 接口文档（网关统一入口）
## 1. 基础信息
| 项 | 说明 |
| :--- | :--- |
| 基础地址 | `http://{网关IP}:8080/api` |
| 通信协议 | HTTP/1.1 |
| 数据格式 | 请求/响应均采用 `application/json` 格式，文件上传采用 `multipart/form-data` |
| 鉴权方式 | 需登录接口在请求头携带 `Authorization: Bearer {token}` |
| 通用响应结构 | 所有接口统一返回标准结构：`{"code": 状态码, "msg": 提示信息, "data": 业务数据}` |

### 通用错误码说明
| 错误码 | 说明 |
| :--- | :--- |
| 200 | 请求成功 |
| 400 | 参数错误/业务异常 |
| 401 | 未登录/Token无效/过期 |
| 404 | 资源不存在 |
| 500 | 服务内部错误 |

## 2. 用户认证模块
### 2.1 用户登录
- **接口名称**：用户账号密码登录
- **请求方法**：POST
- **请求路径**：`/user/login`
- **是否鉴权**：否
- **请求参数**：

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| username | string | 是 | 登录账号 |
| password | string | 是 | 登录密码 |

- **响应示例**：
```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
    "user": {
      "biz_id": "u_xxxxxx",
      "username": "admin",
      "real_name": "系统管理员",
      "dept_biz_id": "d_xxxxxx",
      "phone": "13800138000",

  }
}
```

# 二、RPC 通信文档
## 1. 概述
### 1.1 技术栈
- **通信框架**：gRPC
- **序列化协议**：Protocol Buffers v3
- **服务注册发现**：etcd，键格式 `/services/{服务名}`，值为 `IP:端口`
- **异步解耦**：RabbitMQ 实现异步消息、延迟任务、死信重试

### 1.2 服务总览
| 服务名称 | 监听端口 | Proto文件 | 核心职责 |
| :--- |:-----| :--- | :--- |
| user | 9991 | `user.proto` | 用户认证、部门管理、字典管理、角色权限 |
| asset | 9992 | `asset.proto` | 资产CRUD、状态流转、多人协同盘点 |
| flow | 9993 | `flow.proto` | 领用/报修/报废审批流、二级审核、资产归还 |
| storage | 9994 | `storage.proto` | 文件上传下载、附件管理、物理文件删除 |

---

## 2. 用户服务（user）
### 2.1 UserService（用户认证与管理）
| 方法名 | 功能说明 | 请求消息 | 响应消息 |
| :--- | :--- | :--- | :--- |
| Login | 用户登录验证，生成Token | `LoginRequest` | `LoginResponse` |
| GetUserByBizId | 根据ID查询用户详情 | `GetUserRequest` | `UserResponse` |
| CreateUser | 创建新用户 | `CreateUserRequest` | `CreateUserResponse` |
| ListUserByDept | 按部门查询用户列表 | `ListUserRequest` | `UserListResponse` |
| GetUserRoles | 查询用户角色列表 | `GetUserRolesRequest` | `RoleListResponse` |

#### 核心消息定义
```protobuf
// 请求
message LoginRequest { string username = 1; string password = 2; }
message GetUserRequest { string biz_id = 1; }
message CreateUserRequest {
  string username = 1; string password = 2; string real_name = 3;
  string dept_biz_id = 4; string phone = 5; string email = 6;
}
message ListUserRequest { string dept_biz_id = 1; }
message GetUserRolesRequest { string user_biz_id = 1; }

// 响应
message LoginResponse { string token = 1; UserInfo user = 2; }
message UserResponse { UserInfo user = 1; }
message CreateUserResponse { string biz_id = 1; }
message UserListResponse { repeated UserInfo list = 1; int32 total = 2; }
message RoleListResponse { repeated RoleInfo list = 1; }

// 基础实体
message UserInfo {
  string biz_id = 1; string username = 2; string real_name = 3;
  string dept_biz_id = 4; string phone = 5; string email = 6; int32 user_status = 7;
}
message RoleInfo { string biz_id = 1; string role_name = 2; string role_code = 3; }
```

### 2.2 DeptService（部门管理）
| 方法名 | 功能说明 | 请求消息 | 响应消息 |
| :--- | :--- | :--- | :--- |
| GetDeptTree | 获取完整部门树 | `GetDeptTreeRequest` | `DeptTreeResponse` |
| CreateDept | 新增部门 | `CreateDeptRequest` | `CreateDeptResponse` |
| UpdateDept | 修改部门信息 | `UpdateDeptRequest` | `CommonResponse` |
| DeleteDept | 删除部门 | `DeleteDeptRequest` | `CommonResponse` |

#### 核心消息定义
```protobuf
message GetDeptTreeRequest {}
```

## 6. 异步消息规范
所有服务通过 RabbitMQ 实现异步解耦，统一采用延迟交换机+死信队列机制，默认重试3次，失败进入死信队列。

| 队列名称 | 所属服务 | 消息类型 | 说明 |
| :--- | :--- | :--- | :--- |
| `delete_cache_user_queue` | 用户服务 | 延迟消息 | 清理用户/部门/字典相关Redis缓存 |
| `delete_cache_asset_queue` | 资产服务 | 延迟消息 | 清理资产/盘点相关Redis缓存 |
| `delete_cache_flow_queue` | 流程服务 | 延迟消息 | 清理流程审批相关Redis缓存 |
| `delete_file_queue` | 存储服务 | 普通消息 | 异步执行附件物理删除 |

### 消息体格式
```json
{
  "cache_key": "单个缓存键",
  "cache_pattern": "批量删除通配符"
}
```
