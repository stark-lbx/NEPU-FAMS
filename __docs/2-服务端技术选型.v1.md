### 技术选型
| 技术领域    | 选型方案            | 选型理由                                                                                 |
|---------|-----------------|--------------------------------------------------------------------------------------|
| Web网关框架 | Flask           | 极致轻量，单文件即可启动，配置零门槛，完全满足实训项目开发需求；比 FastAPI 更少约束，上手更快                                  |
| RPC通信   | gRPC + Protobuf | 替代 C++ 的 brpc（Python 生态无官方 brpc 支持），原生支持 protobuf，官方库成熟稳定，开发流程清晰，服务定义与 C++ brpc 思路一致 |
| 注册中心    | 	etcd           | 	与参考代码端口 2379 完全对齐，Python 通过etcd3库即可完成服务注册 / 发现                                      |
| 消息队列    | 	RabbitMQ       | 	与参考代码 AMQP 协议完全对齐，pika库用法简单，支持交换机 / 队列 / 延迟队列，开箱即用                                  |
| 缓存      | 	Redis          | 	标准方案，redis-py库配置简单，支持连接池                                                            |
| 文件存储    | 	FastDFS        | 	沿用参考方案，Python 用py3fdfs库对接                                                           |
| 数据库     | 	SQLite         | 	Python 内置支持，无需额外安装服务，单文件部署，完全匹配你的 fams.db 文件                                        |

### 服务拆分
> （共 5 个子服务，职责解耦、粒度适中）
- 网关服务 svc_gateway：唯一 HTTP 入口，负责鉴权校验、请求路由转发、参数校验，对外提供 RESTful 接口，对内通过 gRPC 调用各子服务
- 用户权限服务 svc_user：用户管理、角色权限、登录注册、Token 签发，对应系统组织架构与权限模块
- 资产管理服务 svc_asset：资产 CRUD、状态变更、盘点任务、盘点明细，对应固定资产核心 + 多人协同盘点模块
- 流程审批服务 svc_flow：领用归还、报修工单、报废申请、多级审批流转，对应所有业务单据与审批模块
- 文件存储服务 svc_storage：附件上传下载、FastDFS 对接、文件元数据管理，对应资产附件模块

---

1、etcd: 服务注册中心, 默认端口2379
2、redis: 缓存服务, 默认端口6379
3、rabbitmq: 消息队列, amqp协议, 默认端口5672
4、fastdfs: 分布式文件存储, tracker默认端口22122
